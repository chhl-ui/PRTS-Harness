## 六、环境变量（运维旋钮）

| 变量 | 默认 | 作用 |
|---|---|---|
| `PRTS_EMBED=1` | 关 | 开启语义检索路；开启时启动阶段自动预热内存索引（3.4 s） |
| `PRTS_EMBED_MODEL` | `bge-m3` | 嵌入模型 |
| `PRTS_RERANK=1` | 关 | 开启交叉编码器精排（需 Python + sentence-transformers） |
| `PRTS_RERANK_MODEL` | `cross-encoder/ms-marco-MiniLM-L-6-v2` | 精排模型 |
| `PRTS_RERANK_PYTHON` | `python` | 解释器 |
| `PRTS_RERANK_TIMEOUT_MS` | `10000` | 单次打分超时 |
| `PRTS_MEMORY_INJECT_LIMIT` | `5` | 注入条数（非法值回落 5，不静默变 0） |
| `PRTS_CONSOLIDATE=off` | 开 | 关闭后台巩固调度 |

所有开关关闭时，检索与注入行为与 v2.17 逐字一致。

## 七、接手须知（三条）

1. **不要在没有真实数据的前提下继续调优**。所有参数都已扫过、模型都已对比过，
   剩下的空间在索引粒度，那是一块需要重建索引的大改动。
2. **`PRTS_EMBED=1` 必须配合预热才有意义**。不预热时语义路只覆盖 19.9% 的 turn 向量，
   实测该状态下混合检索不如纯 bm25（30.9% vs 31.8%，p=0.83）。预热已在 `start.ts` 自动完成。
3. **rerank 是唯一「与查询分布无关」的已证改进**（+9.3pp，产品口径）。索引粒度是另一个，
   但成本高一个数量级。
