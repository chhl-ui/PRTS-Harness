**独立校验**（校验者实现，不复用模型代码）：


## 五、恢复路径（同日补跑，已完成）

第一次跑 V1-10 时两个任务都是一次跑完，没有中断。补跑中断场景后暴露并修掉两处断点：

1. **`recoverOnStartup()` 从未被调用**：`grep -rn "recoverOnStartup" src` 除定义与注释外零调用点（唯一使用者是 `test/ledger/L4-crash-recovery.test.ts:33`）。中断留下的 `started` step 在重启后仍是 `started`——「正在执行」与「进程已死」在账本里无法区分。
   修：`src/runtime/start.ts` 在 `Ledger.open` 之后调用，`started → unknown`，不改任务相位，并打一行日志。
2. **接不回来**：重启时 `describeOpenTasks` 打印「未结任务 1 个……恢复执行请显式操作」，但 `/task-approve` 只处理 draft（要求 `activate`，而 activate 只接受 draft），**没有任何命令能把 active 任务重新绑到新会话**。
   修：新增 owner 命令 `/task-bind <taskId>`（`chat.ts` 的 `runTaskBind`）。`Ledger.bindSession` 本身允许 `draft/active/paused/blocked`（`ledger.ts:471`），缺的只是入口。

真机复跑（`task-86205e48-da32-4fef-81d5-b2039cf08992`）：

| 阶段 | 实测 |
|---|---|
| 中断（`timeout 40` 杀掉正在 `Start-Sleep 45` 的进程） | `phase=active`、`step 1 started`、binding 指向已死会话 `prts-chat-1794236905135` |
| 重启 | `[prts] 启动恢复：1 个中断的步骤已标记 unknown（任务仍 active，用 /task-bind 接回本会话）` |
| 接回 | `/task-bind` → `已把 task-86205e48…（active）接回本会话` |
| 继续 | 模型跑完并 claimDone（step 2–6 全 `succeeded`） |
| 验收 | `phase=done`；事件含 `step.recovered`×1、`task.session-bound`×2；证据 1 条、报告 448 B |

回归：`test\runtime\crash-recovery-wiring.test.ts`（CR1，摘掉 `start.ts` 的调用即红）、`test\cli\task-bind.test.ts`（TB1 接回 / TB2 未知 id 无副作用）。

## 六、附：会话摘要 `fetch failed` 的根因（同日查清）

恢复那轮模型报告「会话摘要写两次都返回 `fetch failed`」。查清如下：

- **不是代码 bug，是依赖缺失**：`prts_memory_summarize` 用 `OpenAIGenerator`，默认端点
  `http://127.0.0.1:8080/v1`（`src/memory/generate.ts:95`）。本机 8080 无服务，实测探针：
  `message: fetch failed` / `cause.code: ECONNREFUSED` / `connect ECONNREFUSED 127.0.0.1:8080`。
- **第二个缺陷（已修）：错误不可诊断**。undici 把真原因藏在 `cause` 里，工具原样抛出，
  模型只能看到 `fetch failed` 四个字。`memory-tools.ts:246` 那句「生成器当前不可用（本地模型可能未启动）」
  是**死代码**——`deps.generator()` 永远返回一个实例（构造不发请求），`undefined` 分支永不触发。
  修法不改可用性，只改可行动性：`generate.ts` 在网络异常时包装成
  `memory: 连不上生成端点 http://127.0.0.1:8080/v1（ECONNREFUSED）。本地模型服务可能未启动；可用 PRTS_SUMMARY_BASE 指向可用端点。`
  回归：`test\memory\generate-endpoint-error.test.ts`（GE1 连不上 / GE2 非 2xx 不误伤）。

要让摘要真的可用，需要起本地生成服务（默认 8080）或用 `PRTS_SUMMARY_BASE` 指向可用端点——属于部署决定，不在代码层。
