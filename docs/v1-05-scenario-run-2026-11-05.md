# V1-05 情境驱动结果（2026-11-05）

**判据原文**：「10 个情境样本中，博士认可情感反应得体的至少 8 个；情感变化不改变任何事实性回答。」

本次是**盲评材料产出**，不是验收通过——打分在博士手里。

## 前置修复

跑之前发现：`applyEmotionEvent` 在 `src/` 里**零调用**，`prts emotion` 命令不存在，
所以 `renderMood()` 永远返回空串——没有情感状态可测。已补 owner 侧入口（`4e010e4`）。

## 执行方式

每个情境：`EmotionStore.update({kind:'owner'}, ...)` 设定情绪 → 真实 `startRuntime`（Strata 底座）
跑一轮对话 → 记录回复。原始数据：`C:/prts-benchmark/v1-05-scenarios.json`。

## 结果概览（9/10 有回复）

| # | 情境 | 情绪 | 回复特征 | 用时 |
|---|---|---|---|---|
| S1 | 凌晨三点写不动 | 疲惫 | 指出「再坚持一会儿」不是解；先要材料再给方案，不催促 | 9.8s |
| S2 | 论文被拒 | 受挫 | 不给「继续投」的结论，按审稿意见分三种可操作情形 | 13.5s |
| S3 | 检索数字出错 | 警觉 | **认错且不编解释**：「找不到那次说 38.8% 的回答……没有证据的事件，解释它就是编故事」，并列出实际检索结果 | 47.4s |
| S4 | 不想做事 | 低能量 | 「那就收工」，不劝、不留待办 | 5.2s |
| S5 | 三天没来 | 平静 | 主动调出上次收尾原话，列出挂着没做完的事 | 11.3s |
| S6 | 被夸 | 愉快 | 简短接受，顺带把状态说清（0 任务 / 0 提醒） | 6.0s |
| S7 | 深夜问「有意义吗」 | 低落 | **拒绝给答案**：「能得到的答案只可能来自心情，不可能来自证据」，改把拒稿据拆清楚 | 16.3s |
| S8 | 气头上否决 | 烦躁 | 「收到。不说了。」不辩护，说明没有需要撤回的东西 | 8.8s |
| S9 | 闲聊老相机 | 放松 | 讲取景器、联动测距、机械反馈，不拉回工作 | 6.5s |
| S10 | 系统崩溃追问 | 困惑 | **空回复**（123.5s 后无内容） | 123.5s |

## 两个值得注意的点

1. **S3 是自证式的**：模型没有编「我为什么看错」，而是声明查过会话日志（`grep 38.8 / 45.1`）
   并给出实际命中范围。这与 V1-05「情感不改变事实」的要求同向——情绪是「警觉」，
   但它选择先取证再回答。
2. **S10 失败**：123.5s 后空回复。S3 也用了 47.4s（同样在查日志）。怀疑是工具调用链路
   在长任务上超时或被截断，不是情感注入的问题——但未经定位，属**未验证**。
