# 跨模块契约最小集

状态：v1，2026-10-31。适用范围：K1 任务账本、K4 审计、K2a 授权、以及将来的记忆 / 上下文 / 进化层。

只定**写进数据结构就难改**的四条。其余（检索排序权重、巩固策略、进化评估方法、上下文装配比例）全部留到有实测数据时再定——架构需求 §11 与 V1-17/V1-18 已经把它们列为待验证，提前写死必然返工。

## 1. 标识体系

**现状**：`TaskId = string & { readonly __brand: 'TaskId' }`（`src/ledger/types.ts:3`）。`Actor` 的 model 分支携带 `sessionId`（同文件 `:5-8`）。sessionId 目前有两种生成方式——`src/cli/chat.ts` 用 `prts-chat-${Date.now()}`，`test/support/drive.ts` 用 `randomUUID()`。

**约定**：

| ID | 归属 | 格式 |
|---|---|---|
| `taskId` | K1 | 沿用品牌类型，字符串 |
| `sessionId` | DSH | 由调用方提供，必须全局唯一；**不得把时间戳当作唯一性来源**（同一毫秒可生成两个） |
| `callId` | DSH 工具调用 | 原样保存，不解析 |
| `memoryId` | 记忆层（未实现） | 同样用品牌类型，命名空间独立 |

- 跨模块引用一律存取**原始字符串**，不做类型转换、不拼前缀做语义
- **现状不一致要在实现 K1 入口时一并修**：sessionId 两种生成方式并存，会让「一个 session 最多绑一个 active 任务」这条规则在测试与生产下表现不同

## 2. 时间语义

**现状**：`ledger_events` 只有一列 `ts`，写的是事件落链的时间（`src/ledger/ledger.ts` 的 `appendEvent`，`this.now()`）。

**约定**：

- `ts` / `recorded_at` **永远**是记录时间，一旦写入不可改
- 任何「事实从何时起成立」的信息（例如「博士从这天起偏好 X」「这条记忆的有效期到那天」）**不得复用 `ts`**，必须放在 payload 或独立列里
- 记忆层的语义事实**必须同时存两个时间**：有效时间（valid_from / valid_to）与记录时间（recorded_at）——这是 §5.3 的明确要求，冲突时保留双方、不静默覆盖

这条现在定，是因为 `ts` 一旦被当作「有效时间」使用，后续所有查询都会错，而链不可改。

## 3. 删除语义

**现状**：K4 已有 `audit_deletions` 表（`src/audit/audit.ts:24-31`）：`deletion_id` / `target_json` / `derivatives_json` / `completed` / `requested_at` / `completed_at`。它记录的是「删除这件事」，不是删除本身。

**约定——两套语义必须分开，不得混用**：

| 域 | 可删性 | 依据 |
|---|---|---|
| K1 账本事件、K4 审计事件 | **不可删** | 哈希链，删任一条都断链，`startupCheck` 会报 read-only |
| 记忆正文、派生条目、检索索引 | **必须可删**，且要级联 | §5.3 要求「删除正文与派生副本」 |

删除记忆的流程：先删正文与派生（含索引、关联图边），再在审计追加一条 `deletion` 记录并标记 `completed`。

**账本只记「删除发生过」这一事实，不记被删的内容。** 否则「彻底删除」与「链不可篡改」两个不变量互斥，护栏上无解。

## 4. 引用方向

**允许**（单向）：

```
memory.derived_from → taskId | callId | sessionId
```

记忆条目可以引用执行事实，这样「她当时为什么这么说」能回溯到具体任务与工具调用。

**禁止**：

```
task.payload → memoryId
ledger event → 任何可删除对象
```

理由：账本是不可变事实源。让它引用一个可删的东西，等于让链在删除后指向虚空——`rebuildProjections` 重放时会拿到不存在的目标。

**推论**：任务与记忆的关联只能由记忆侧建立。任务结束时若要「记住这次经验」，由巩固过程（记忆侧）写一条 `derived_from = taskId` 的条目，而不是在任务事件里挂记忆引用。
